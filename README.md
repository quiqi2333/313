# 313

**把反复交代的协作习惯，整理成一份可复用的 Skill。**

313 是一份面向设计、研究和多轮成果迭代的个人协作技能。它约定了资料如何阅读、任务如何分派、分析与制作如何配合，以及修改时哪些内容需要保留，让长项目里的协作方式更稳定。

## 为什么做 313

一个项目做久了，往往会反复说明同样的要求：

> 先读任务书和 PDF，再结合已有成果分析。  
> 让 Luna 读取资料，让 Astra 判断怎么做。  
> 这次先分析，不急着生成。  
> 这段文字已经定了，只改我标出的部分。  
> 参考图的配色和比例，也要落实到成图里。

313 从这些实际使用习惯中整理出一组简短规则。调用之后，主代理可以按任务情况自主安排分工，同时保留用户当次调整的空间。

## 适合哪些任务

- **课程与竞赛设计**：结合任务书、老师要求、PDF/PPT 和现有方案推进。
- **调研与方案比较**：阅读相关资料，比较可行方向、优缺点和实际案例。
- **图表、展板与视觉修改**：对照参考，检查颜色、比例、排版与材质等指定细节。
- **作品集及多轮成果迭代**：沿用已确认内容，聚焦本次需要修改的部分。

简单问答和小改动可以直接完成，无需启动整套分工。

## 默认怎样分工

| 角色 | 默认设置 | 主要负责 |
| --- | --- | --- |
| Luna | GPT-6 Luna · 极高 | 读取材料、检索资料和执行制作 |
| Astra | GPT-6 Astra · 中 | 分析判断、方案规划，并指导复杂制作 |
| 主代理 | 当前主持任务的代理 | 拆分任务、分派子代理、整合与检查结果 |

主代理可以自行决定是否需要子代理、怎样分配任务。独立工作可以并行，有前后依赖的工作按顺序交接，不需要用户每次手动指定分工。

**用户当次指定的模型、强度和分工优先。** 这些设置表达的是个人协作偏好，不是模型能力排名。运行环境需要实际支持相应模型与子代理；313 不会安装模型、增加操作权限或修改全局模型配置。

## 六组协作规则

1. **按任务分工**：根据任务规模自主委派，复杂工作由分析与执行配合完成。
2. **先理解相关材料**：阅读本次需要的任务书、老师要求和已有成果，再形成判断，无需每轮重读全部历史。
3. **尊重当前阶段**：要求先分析、先比较或先文字时，按该阶段推进；明确要求制作时，继续完成已授权的制作。
4. **保留已确认内容**：保留明确要求沿用的文字、数据、底图、构图、结构与范围，按指定位置修改。
5. **选方案时比较**：需要选型时，比较可行方向、优缺点及相关实际案例。
6. **核对视觉参考**：检查本次指定的配色、比例、排版、材质和修改要求是否落实，不把某次风格固定为永久偏好。

完整规则见 [SKILL.md](SKILL.md)。

## 如何使用

将本仓库内容放入个人技能目录下的 `313` 文件夹，保留以下结构；已有同名技能时先保留自己的版本，再决定是否替换。

```text
313/
├── SKILL.md
├── README.md
└── agents/
    └── openai.yaml
```

在支持该技能的 Codex 环境中，可以这样发起任务：

```text
$313
先阅读这份任务书和现有 PPT，分析当前方案还缺什么，这轮先不要制作。
```

也可以在当次任务里覆盖默认分工：

```text
$313
这次让 Luna 6 高读取材料，Astra 分析，先比较三个方向的优缺点。
```

如果环境支持从 GitHub 安装 Skill，也可将本仓库链接交给相应安装器处理。
